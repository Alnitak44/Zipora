# Zip Slip 安全解压防护

从 2.0.44 起，Zip Slip 防护为默认开启的可选功能，与压缩炸弹防护分别设置。

## 使用

- 在“设置 → 功能 → Zip Slip 防护”开关此功能，初次启动及旧配置升级均默认开启。关闭时需确认；取消确认、关闭提示窗口或 Alt+F4 都会保持开启。
- 主页没有手动检查入口。开启时，在建立目录树、显示内容前自动检查；文件名加密的压缩包在获得密码后、显示目录前检查。
- 安全检查只读取当前层的目录元数据，不提取文件，不调用云查询；失败或取消不会标记为检查通过。
- 发现风险时显示条目和原因，并停止打开。超过 200 项时保留总数并截断明细。
- 设置立即生效并保存，下次启动继续使用；常规版和 Portable 行为相同。关闭会停止自动扫描与额外提取预检，原有选中项路径验证和输出边界检查仍保留。

## 自动检查

防护开启时，打开压缩包时检查目录；每次实际解压时重新读取目录，不依赖界面的旧记录。整包解压、选中项解压、拖拽解压、双击临时打开文件及资源管理器命令行入口共用底层策略。

检查内容包括 `..`、绝对/UNC/设备路径、盘符相对路径、NTFS 备用数据流、控制字符、Windows 保留设备名、尾部点/空格别名、大小写冲突、文件与目录冲突，以及符号链接/硬链接。ZIP 的原始中央目录和 TAR 的原始元数据额外检查，防止换行文件名在 7-Zip 文本清单中失真；不支持的 TAR 特殊条目同样阻止交付。

检查目标路径及其所有已有父目录，拒绝符号链接、目录联接和重解析点。底层解压接口拒绝覆盖已有文件，避免覆盖已有硬链接；正常界面使用新的暂存目录，完成后交付到新的目标文件夹。解压完成后再检查提取树，不交付链接条目。

压缩包主文件在底层预检到提取结束期间以只读共享方式保持打开，阻止常规的替换和修改。取消预检不会创建目标目录。

## 范围与限制

- 检查的是当前压缩层的路径，不扫描病毒，也不替代完整性校验。嵌套压缩包要在打开内层时重新检查。
- 一旦发现危险条目，整包及选中项提取均阻止，不能通过仅选择其他条目绕过。
- 某些 7-Zip 支持而 .NET 无法读取中央目录的特殊 ZIP（例如部分分卷 ZIP）会显示“无法完整验证原始 ZIP 文件名”，并阻止解压；不会把未完成的检查误报为安全。
- 这是应用级防护，不是操作系统沙箱。检查和写入仍有时间差；无法承诺抵御拥有本地目录修改权限的恶意进程持续并发替换目录，也不封锁其他进程修改分卷的所有成员。使用可信的本地目标目录，持续维护官方 7-Zip 引擎。

## 验证

```powershell
dotnet run --project tests/PathSecurityRegression -c Release -- artifacts/path-security-test src/Zipora/7zip/7z.exe
dotnet run --project tests/ExtractionRegression -c Release -- artifacts/extraction-test src/Zipora/7zip/7z.exe
```

使用新的输出目录。安全回归会在该目录内构造恶意 ZIP/TAR、目录联接、硬链接和正常样本，确认危险包在创建解压目录前被拒绝、外部哨兵文件未被修改；需要允许本地创建测试链接。提取回归同时覆盖真实 Windows Shell 虚拟文件复制、延迟拖拽、空目录、加密包和取消清理。

设计参考：[Microsoft — ZIP and TAR best practices](https://learn.microsoft.com/en-us/dotnet/standard/io/zip-tar-best-practices)。
